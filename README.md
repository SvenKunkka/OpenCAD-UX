# OpenCAD UX

> A Fusion-inspired **Product Design workspace for FreeCAD**, focused on
> consumer-electronics ID & mechanical design: keyboards, mice, headsets,
> receivers, charging docks and enclosures.

OpenCAD UX is **not a clone** of FreeCAD's interface: it is an add-on Python
workbench that gives FreeCAD a product-design oriented, high-information-density
workspace with an original look (own icons, own themes), while every operation
is executed through FreeCAD's **public APIs and standard commands**. Nothing
about Autodesk, Fusion 360 or its assets is reproduced — only generic CAD
interaction patterns that are not protected (two-point sketches, pad/pocket,
boolean combine, ribbon-style grouping …) were studied.

## Feature list

- **Product Design workspace** (single workbench for the model workflow) that
  hides modelling-irrelevant workbenches only by *default preference*; no
  FreeCAD workbench is removed and everything can be re-enabled in Settings.
- **Ribbon UI** defined entirely by `resources/ribbon.json` (7 groups, 53
  buttons): Sketch / Constraints / Create / Modify / Combine / Inspect /
  Insert-Export. Groups and buttons are adjustable without touching code.
- **Original icons** — 61 flat SVG glyphs ×2 themes generated by
  `scripts/make_icons.py` (no Autodesk/other proprietary art).
- **Light & dark themes** (own palettes) with live switching and one-click
  restore of the previous stylesheet.
- **Fusion-inspired shortcut preset** with conflict detection (per-platform:
  `mod` = Ctrl on Win/Linux, ⌘ on macOS), import/export, apply / restore
  FreeCAD defaults. Shortcuts are delivered by an *overlay* while the Product
  Design workspace is active, so your FreeCAD shortcuts are **never modified**.
- **Command search** (press **S**): bilingual fuzzy search (EN + 中文),
  recents boost, icon/name/group/shortcut rows, context-aware availability,
  real FreeCAD commands on Enter.
- **Context actions** (press **Q** or dock panel): actions adapt to the
  current selection (sketch, face/edge hints, multiple solids, reference
  images …).
- **Reference image workflow**: import PNG/JPG, attach to XY/XZ/YZ planes,
  quick width calibration, two-point calibration math, opacity, visibility,
  lock (uses FreeCAD `Image::ImagePlane`, public API).
- **Safe command runner**: native command where available, python fallback
  otherwise, friendly error messages when an action cannot be done with the
  stock public API (e.g. Fusion-style *Move Face* / *Offset Face*).
- **Settings page** (Appearance / Ribbon / Navigation / Shortcuts / Workflow /
  System) incl. backups & restore of the config files FreeCAD writes.
- **Examples**: three real parametric consumer-electronics models
  (keyboard shell, mouse concept, enclosure with screw bosses & USB opening)
  generated by scripts and saved as real `.FCStd` (+ STEP/STL export).

## Installation

### Via Addon Manager (recommended, when published)

Tools → Addon Manager → search *OpenCAD UX* → Install → restart FreeCAD →
switch to **Product Design (OpenCAD UX)**.

### Manual installation

1. Download the release ZIP (`OpenCAD-UX-0.1.0.zip`) from the Releases page.
2. Unzip it so that the folder contains `package.xml`, `Init.py`,
   `InitGui.py` and `opencad_ux/`.
3. Put that folder into FreeCAD's user `Mod` directory
   (File → “Open user's configuration directory” shows the location;
   on macOS it is `~/Library/Application Support/FreeCAD/<version>/Mod`).
4. Restart FreeCAD and select **Product Design (OpenCAD UX)** from the
   workbench switcher.

Command-line helpers in this repo:

```bash
bash scripts/install.sh          # detects FreeCAD, backs up config, copies
bash scripts/uninstall.sh        # restores backups and removes the addon
bash scripts/make_zip.sh         # builds the distributable ZIP
```

`install.sh` **backs up your FreeCAD config files before touching anything**
(they are stored under `<user data>/OpenCADUX/backups/`) and prints exactly
what was changed. The add-on keeps its own settings in the FreeCAD parameter
group `BaseApp/Preferences/OpenCADUX` — nothing else in your preferences is
modified unless you explicitly apply a theme/navigation preset (both of which
record the previous value for restoration).

## Mouse & navigation

FreeCAD 1.0/1.1 (including 1.1.3) has **no built-in Fusion navigation style**.
The add-on therefore:

1. probes for a native Fusion style and uses it when the running build ships one;
2. otherwise applies the closest built-in (**Revit** by default: wheel zoom,
   middle-drag pan …) via FreeCAD's own navigation parameter
   (`BaseApp/Preferences/View/NavigationStyle`);
3. documents which behaviour differences cannot be recreated from python (see
   below).

| Desired (Fusion-like) | Python layer on stock FreeCAD |
|---|---|
| Middle-drag = pan, Shift+middle = orbit | Not remappable through public APIs (all versions to 1.1). Revit applied instead. |
| Wheel zoom | Native. |
| Double-click cube / Fit view (Shift+F) | Native `Std_ViewFitAll`. |
| View presets (front/back/left/right/top/bottom/iso) | Native `Std_ViewFront` etc. |

A native **C++ navigation patch** is *not* required for the MVP: the parameter
based Revit mode is applied; a later optional native module would be the only
way to get a pixel-exact Fusion mapping. Choosing `fusion` in Settings falls
back to Revit automatically when no Fusion class exists.

## Settings backup & restore

- Settings dialog → **System** → *Back up settings now* copies the FreeCAD
  `user.cfg`/`system.cfg` (only the files FreeCAD itself maintains) to
  `<user data>/OpenCADUX/backups/settings/`.
- *Restore from backup* puts the most recent snapshot back (restart FreeCAD).
- *Restore default layout* resets the OpenCAD UX parameter group and removes
  the ribbon/context docks; FreeCAD's own UI is never destroyed by it.
- `scripts/uninstall.sh` runs a small python snippet inside FreeCAD to remove
  the parameter group and restores the stylesheet the add-on saved before
  applying a theme.

## Known limits

- **Fusion-style Move Face / Offset Face** do not exist in the stock FreeCAD
  public API (any version). Clicking them explains this and suggests
  alternatives (`Transform`, editing the source sketch, `Thickness`).
- PartDesign fillet/thickness **feature objects** cannot be authored from
  python headlessly (their edge/face references need the GUI task dialogs);
  the examples therefore apply fillets/shells through the equivalent OCC
  shape operations (`Part.Shape.makeFillet/makeThickness`) and keep the
  primary profile fully parametric.
- Live mouse remapping and press/pull-like direct manipulation are not
  possible from python on stock FreeCAD (see navigation table).
- The ribbon is a dock hosted by the FreeCAD main window; if another global
  UI add-on (e.g. FreeCAD-Ribbon) also restructures the window the two can be
  used together, but layouts may fight — disable one of them in that case.
- GUI automation on this development machine is limited by a known Qt/macOS
  accessibility crash (see `docs/DEVELOPMENT.md`), so ribbon behaviour was
  verified with the in-GUI self-test command rather than pixel automation.
- No full *Fusion-style* left mini-toolbar / right-clicks on shapes yet; the
  context panel + Q menu is the implemented MVP of contextual actions.
